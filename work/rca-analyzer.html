Agentic AI RCA Analyzer & Pipeline Debugger

The problem

Airflow DAGs across the enterprise failed frequently for mundane but noisy reasons — schema drift, auth rotations, transient GCS throttling, upstream data arriving late. On-call engineers spent most of their shift repeating the same triage: open log, read traceback, scan recent commits, check upstream health, write a RCA. Mean time to diagnosis was 45–60 minutes even when the fix was a one-liner.

The approach

A chain of Gemini 2.5 Pro agents that run automatically when a DAG fails:

  • Collector — pulls the failed task's logs, upstream task state, recent code changes (Git), schema snapshots and the last 10 historical failures of the same task.
  • Classifier — categorizes the failure (SchemaDrift · AuthExpired · UpstreamLate · ResourceLimit · UnknownException) and attaches a confidence score.
  • Historian — queries past incidents for near-matches by stack trace embedding + task fingerprint; surfaces the fix that resolved them.
  • Writer — generates the RCA document: summary, timeline, root cause with evidence, recommended fix (one-liner where possible), owners to notify.

Output drops into a structured incident doc + Slack thread; the on-call reviews rather than writes from scratch.

What made it work

  • Confidence-scored output — on-call ignores low-confidence recommendations instead of being misled by them.
  • Historical correlation — most "new" incidents are repeats; past fixes are the strongest signal.
  • Narrow prompts per agent — classifier only classifies, writer only writes. Each step is independently testable.
  • Human-in-the-loop — the RCA is a draft, not a decision. Engineers edit, Jira tracks the final version.

Results

  • Debugging time cut by ~30% across the pilot team (measured over 6 weeks, N≈120 incidents).
  • RCA documentation went from "sometimes" to "every incident" — compliance teams noticed.
  • Repeat incidents down because every past fix is now searchable, not buried in Slack history.
