The problem

A 300+ application migration from on-prem to GCP needed a lineage map per application: what tables are read, what tables are written, which DAGs depend on which, and where the risky cross-file references live. Doing it by hand was taking engineers 2–3 days per app, and the maps rotted the moment the codebase changed.

Pure static analysis caught the easy cases but broke on dynamic SQL, templated Jinja and operators that construct names at runtime.

The approach

A hybrid: deterministic parsing where it works, Gemini where it doesn't. See the interactive diagram on the home page for a hover-through of the pipeline.

  • AST Parser — Python AST walks over DAG definitions and operators to pull imports, task graph, SQL strings, GCS paths and params.
  • Gemini Analyzer — resolves dynamic names, templated SQL and non-obvious lineage. Returns structured JSON with a confidence score per edge.
  • Dependency Graph — networkx builds the full lineage; low-confidence edges get flagged for human review.
  • HTML Flow Viz — interactive D3 visualization: searchable, filterable, per-table lineage and risk tiers.

Architecture (simplified)

GCP Codebase ──► AST Parser ──► Gemini Analyzer ──► Dependency Graph ──► HTML Flow Viz
                  (static)       (Agentic AI)         (networkx)             (D3 · Jinja)

What made it work

  • LLM only where static analysis fails — kept cost down and accuracy up. Deterministic layer handled 70%, Gemini handled the hard 30%.
  • Confidence per edge — the migration team trusted the graph because they could see what was certain vs. inferred.
  • Interactive output — a browsable HTML report beat a static PDF every time. Engineers kept it open on a second monitor.
  • Re-run cheap — the whole pipeline runs in minutes per app, so the lineage stays fresh as the codebase changes.

Results

  • Manual discovery effort down 65% across the 300+ app program.
  • Lineage accuracy up 40% vs. the earlier static-only baseline.
  • Further ~20% reduction in rework as teams caught lineage gaps before migration, not after.
